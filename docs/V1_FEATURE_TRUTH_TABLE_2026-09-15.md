## V1 acceptance tests and failure responses

| V1 feature | Concrete acceptance test | Customer support response when it fails |
|---|---|---|
| Trial and entitlement | Create fresh, active-trial, expired, Plus, Complete, refunded/revoked, and admin accounts; verify every route and server-paid action against the table above. | Confirm account email and diagnostic ID, check entitlement and payment by stable IDs, restore only from verified evidence, and never ask for a password. |
| Expired paywall and deletion | Advance a test trial beyond its expiry; confirm no app route, browser back action, or direct view opens; separately complete data deletion and account deletion from the wall. | Keep the account locked; provide the public deletion path or retry steps; escalate partial deletion immediately and confirm completion without requesting financial details. |
| Authentication and MFA | Exercise signup, verification, login, logout, recovery, expired/reused links, changed email, MFA enroll/challenge/disable, and session timeout in supported browsers. | Verify identity through approved account signals, resend or restart the affected flow, revoke suspect sessions, and never request a password, MFA secret, or login link. |
| Save and sync | Create, edit, and delete every record type against a production-shaped database; refresh during save; simulate offline/reconnect and two-tab/two-device edits; confirm “Saved” matches the server. | Tell the customer to stop editing if loss is possible, preserve timestamps and diagnostic ID, check the server record, restore the latest verified version, and escalate any silent loss as launch-blocking. |
| Overview and calculations | Run fixed, independently calculated examples plus zero, decimal, negative, large-value, month/year boundary, leap-year, and time-zone cases; compare every dependent screen and export. | Record the inputs without account numbers, reproduce independently, label the output under investigation, correct all dependent outputs, and pause sales for a material incorrect calculation. |
| Budget | Add, edit, duplicate, back-date, future-date, and delete each entry type; verify totals, month assignment, score, charts, goals, reports, and cloud state. | Identify the affected month and action, avoid requesting a full financial export, reproduce with synthetic values, restore data if needed, and escalate wrong totals or lost entries. |
| Debt tracking and scenarios | Verify baseline and accelerated schedules for zero rate, high rate, minimum-only, extra payments, overpayment, and impossible payment; independently compare payoff month and interest. | Ask for synthetic balance/rate/payment values, reproduce, explain estimates, correct the calculator, and treat materially wrong payoff guidance as a release blocker. |
| Net worth and projections | Add/edit/delete assets and liabilities; verify current total and projections under zero, negative, and large values across screen and reports. | Confirm the affected record type and date, reproduce with synthetic values, correct the projection, and disclose that forecasts are estimates. |
| Calculators | For every calculator, test required fields, zeros, decimals, extremes, invalid dates/rates, keyboard use, mobile-width reflow, and fixed expected answers. | Request the calculator name and synthetic inputs, provide a safe manual workaround only if verified, and remove access if the result may be misleading. |
| Goals | Delete a goal linked to a budget contribution and confirm the budget row remains as an unassigned goal contribution locally and after cloud save; verify limits and forecast dates. | Tell the customer not to recreate missing rows until checked, inspect the goal and budget records, restore any lost row, and escalate recurrence as a data-integrity incident. |
| Smart alerts | Seed each rule and its resolved state; verify no financial amount appears in notification previews, the correct destination opens, read state persists, and irrelevant alerts disappear. | Explain the alert is planning guidance, ask for its title (not financial figures), verify the underlying rule, correct or disable a noisy rule, and never claim an alert is professional advice. |
| Reports and exports | Generate every plan-allowed format with representative, Unicode, formula-like, and adversarial data; open in Excel, Google Sheets, common PDF readers, and supported mobile browsers; compare identity, period, and totals. | Ask for report type, period, app version, and error code—not the report itself by default; regenerate securely and treat cross-customer content as a critical privacy incident. |
| AI Health Coach | Verify Complete/trial authorization, Plus/expired denial, quota, timeout, injection-like input, long input, malformed/refused/empty output, provider outage, exhausted credit, privacy notice, and local unavailable state. | State that personalized coaching is temporarily unavailable, preserve deterministic calculations, collect only timestamp/error code, never request the prompt or financial values, and disable the feature if unsafe output is reported. |
| Search and navigation | Use keyboard and pointer to search each route and record type; verify exact destination, focus, mobile menu, browser back, and no admin-only leakage. | Ask what the customer searched for and expected, provide the direct safe route, and escalate any cross-account/admin result immediately. |
| Settings and data controls | Toggle every preference, refresh, change sessions, export/delete data, and verify security-sensitive actions require appropriate authentication. | Confirm the setting name and browser, help restore the preference, and route privacy/deletion failures through the deletion incident procedure. |
| Essentials workbook | Create a verified account, claim once and again, test an expired/replayed capability, open the personalized file in Excel and Google Sheets, and verify correct owner/license with no master exposure. | Verify the account, regenerate a short-lived download, never email an unrestricted master, and treat another customer’s workbook as a critical privacy incident. |
| Feedback and support | Submit from each high-risk error state and confirm delivery, acknowledgement, categorization, reply path, unsubscribe boundaries, and retention without financial content. | Acknowledge receipt, give a realistic next update, use the diagnostic ID, and keep passwords, secret links, prompts, and detailed financial data out of the ticket. |
| Admin business accounting | With a customer account, verify no navigation, route, component, table, or API access; with an AAL2 admin, exercise entries and exports using synthetic company data. | Do not describe it as a customer feature; lock access, preserve audit evidence, and require founder approval plus accountant review before relying on it as company books. |

## Approval rule

Only the founder may change a feature from “Later” to launch scope, change plan inclusion, approve customer wording, or accept a failed acceptance test. A code implementation alone does not change this table’s “Verified” status.
